Shrinking tokens from 32 to 17 bytes doubled lexing speed on real code

Each token stored by lex_file went from a word-sized type, a location and a 16-byte slice to a 1-byte type, a location and an 8-byte length. Same lexer logic, same input files, 10 timed runs per file.

$ make bench-lexer  ·  3 files × 64 MB  ·  10 runs + 1 warmup

Why

Token storage written per 64 MB file

Token count × bytes per token. Before the change, the dense file wrote about 25 times its own size in token records. After, it writes about 13 times.

One square = one byte. Tokens are stored #soa, so each field lives in its own array and the 1-byte type needs no padding.

Setup

Apple M1 Pro, 16 GB, macOS 26.4.1. Odin dev-2026-04-nightly, built with -o:speed. Read is os.read_entire_file on a file already in the OS page cache. Lex is lex_file on bytes in memory, including building the token array. Before and after were measured in separate runs a few minutes apart.
